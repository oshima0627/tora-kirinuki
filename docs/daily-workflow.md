## 1本作る

### 1. 本編を取る

```bash
python scripts/fetch_source.py --latest 5 --list
python scripts/fetch_source.py https://www.youtube.com/watch?v=<video_id>
```

`work/<video_id>/` に `source.mp4` / `subs.json` / `meta.json` が出ます。
44分の動画で約380MB、取得に1〜2分。

### 2. 信号を集める

```bash
python scripts/probe_signals.py <video_id>
```

音量の測定に尺の1割ほどかかります（44分で約35秒）。

ヒートマップは**新しい動画には存在しません**（実測で30本中7本のみ。
条件は「5万回以上」かつ「3週間以上経過」の両方）。無くても他の3信号で動きます。
過去回を掘るときだけ、ブラウザで取った `ytInitialData` を `--ytdata` で渡してください。

### 3. 候補を見る

```bash
python scripts/find_moments.py <video_id> --count 5 --length 900
```

**尺は13〜20分を狙います。** 「令和の虎 切り抜き」の検索上位25本はすべて14〜70分で、
日次で回している競合も13〜15分と20分でした（2026-08-13 実測）。
当初の420秒はこの市場では明確に短すぎます。総再生時間（YPPの3,000時間）にも効きます。

### 判定パートばかり切らないこと

出力にはこう出ます。

```
1. 00:39:19-00:54:21  71%地点  score=139.7  [詰め6 判定1 金額12 コメント1]  ...
```

**`%地点` と `[内訳]` を見てください。** 最初の8本は全部が平均79%地点、
つまり終盤の判定パートからの切り出しで、うち6本が完全ALLの成功譚でした。
一方この市場で伸びているのは「虎がブチギレた回」「激詰め」——**中盤の対立**です
（2026-08-13 実測）。スコアだけで選ぶと判定パートに寄ります。

詰めどころを狙うときは重みを上げられます。

```bash
python scripts/find_moments.py <video_id> --length 900 --prefer 詰め
```

ただし**1位が入れ替わるとは限りません**。判定パートは金額の語彙が多いので
スコアが出やすい。最終的には内訳と位置を見て人が選びます。

**詰めだけを繋いだ編集にしないこと。** ガイドラインの「出演者の名誉を害する編集」に
触れます。虎が代案を出している、構造を整理している、といった中身のある区間を選べば
図解の題材としても成立します（実例：9本目は谷本社長が法人向けサブスクの代案を
その場で組み立てる15分を切りました）。

候補と一緒に「金額の言及」が出ます。案件カードの下書きに使えますが、
**字幕はASRなので金額は必ず映像で裏取りしてください。** 令和の虎は金額が命です。

### 4. レシピを書く

`recipes/_example.json` をコピーして `recipes/<id>.json` を作ります。
`clip` は候補から選び、カードの中身は映像を見て書きます。

`cards.brief.amount` が空だとビルドが止まります。裏取り前の公開を防ぐためです。

**サムネの `thumb.faces` は被写体を外側に寄せて置きます。** 中央に顔があると
吹き出しが必ず顔に被ります。既定は外側34%の位置で、寄せ具合は各 face の
`bias`（0〜0.5、小さいほど外側）で調整できます。

**立位の人物は `crop_top` で頭上の余白を調整します。** 関西版の進行役が壇上に
立つカットのように頭がフレーム上部に近いと、既定の切り取り（上から17%を落とす）
だと頭が切れます。その face だけ `crop_top` を小さく（例: 0.04）すると直ります。
逆に、顔の左右に避けたいキャプションボックスがある場合は `crop_top` を大きくして
寄る（ズームインする）と、ボックスとボックスの間の安全な帯に収まりやすくなります。

**画面下いっぱいの会話テロップは `crop_top` では避けられません。** 切り取りの下端は
常にフレーム最下端に固定される仕組みなので、`crop_top` を上げても下のテロップは
消えず、頭が余計に切れるだけです。会話テロップが画面下に出ているカットは
`crop_bottom`（例: 0.22）でテロップ帯ごと落としてください。

**画面左上の名前テロップは「志願者の情報」の固定表示で、その瞬間に画面に映って
いる人物とは限りません。** 顔を抜くフレームを選ぶときは、名前テロップだけで
判断せず、実際に画面に映っている人物が誰かを（一人称で話しているか、画面右下等の
個別ラベルがあるか）確認してください。吹き出しの発言も、誰が言ったかを字幕の
タイムコードで裏取りしてから割り当てます。

サムネ生成後は必ず PNG を目視確認してください（実例：5本目で頭切れ・人物取り違え・
発言者の取り違えが発生し、いずれも修正済み）。

**吹き出しは口元の高さに出ます。** 顔は顎に向かって細くなるので、
目元より口元のほうが左右の余白を取れます。目元の高さは顔の最大幅にあたり、
外側に寄せてもぶつかりました（実際に2回作り直しました）。

**論点カード（`cards.points`）は画面の上部に出ます。** 令和の虎Secondは画面下部に
大きなテロップを常時焼き込んでいるので、下に置くと必ずぶつかります。実ビルドで
確認したところ、帯からはみ出した元の文字が上下に残って両方読めなくなりました。

**内容が元のテロップと重複しないか確認してください。** 元動画は要点を大きな文字で
焼き込んでいるので、同じことを書くと二重になります。**元が言っていないこと**
——構造の整理、数字の位置づけ、前後の文脈——を書くほうが価値が出ます。

**動画を上げる前に必ずフレームを抜いて確認してください。** 上げてから直すと
動画IDが変わり、古い動画を消す手間が出ます（実際に3本消しました）。

**ただしタイトル・概要欄・タグだけなら上げ直さずに直せます。**
`python scripts/sync_metadata.py recipes/<id>.json` でレシピの文言を公開済みの
動画へ反映します。動画IDも再生数も維持されます。映像を直すときだけ上げ直し。

### タイトルの型（2026-08-13 実測にもとづく）

「令和の虎 切り抜き」の検索上位はほぼ全てこの形でした。

```
【令和の虎】虎「発言の引用」志願者「発言の引用」内容【令和の虎Second 切り抜き】
```

冒頭の `【令和の虎】` と末尾の `【令和の虎切り抜き】`、そして**発言の引用の対**が
共通項です。要約文だけのタイトルは検索クエリに当たりません。
ショートはさらにハッシュタグを本文に入れます（`#令和の虎 #切り抜き #ビジネス #起業`）。

引用は**元動画の焼き込みテロップから取ること**。ASR字幕は固有名詞と数値が崩れます。

### 5. ビルドする

長尺とショートを**同じレシピから**作ります。素材・候補・カードの文言を共有できるので、
ショートを足しても調べ直しが要りません。

```bash
python scripts/build_clip.py  recipes/<id>.json --dry-run
python scripts/build_clip.py  recipes/<id>.json     # → work/<id>/
python scripts/build_short.py recipes/<id>.json     # → work/<id>-short/
```

再生して、カードの位置と尺を目で確かめてください。

**ショートは `short` ブロックが要ります。**

**尺は60〜70秒。** 伸びている競合を実測すると令和の虎塾が67〜73秒（公開1〜4日で
3,925〜28,477再生）、【忙しい人のための】が22〜37秒でした。こちらの103秒・132秒は
0〜2再生です。**動きのある瞬間だけを取ること。** 座って話しているだけの2分は完走されません。

| 項目 | 意味 |
| --- | --- |
| `start` / `end` | 切り出す区間。**60〜70秒に詰める**（180秒を超えると落ちるが、75秒を超えた時点で警告が出る） |
| `hook` | 上部に出す一文。**空だとビルドできない**（縦型は冒頭2秒で離脱が決まる） |
| `footer` | 下部の図解。金額や判定など、映像だけでは分からない情報 |
| `title` | 省略すると `hook` が使われる |

**縦型では映像を縦にトリミングして顔を大きくしています**（`build_short.py`）。
上下の黒帯が元動画の告知と字幕を覆うので、図解と二重になりません。

かつてここには「クロップしない」と書いてありましたが、コードは実際には
クロップしています。**画面に占める映像の割合は、伸びない原因ではありませんでした。**
28,477再生の競合ショートを落として採寸したところ、映像領域はこちらより小さいくらいでした
（2026-08-13）。効いていたのは尺と、文字の太さと、動きの有無です。

### 6. 投稿する

```bash
python scripts/upload_youtube.py work/<id>                  # 長尺 private
python scripts/upload_youtube.py work/<id> --publish
python scripts/upload_youtube.py work/<id>-short            # ショート private
python scripts/upload_youtube.py work/<id>-short --publish
```

`expected_channel_id` が一致しないとアップロードしません。
ショートには `#Shorts` タグが自動で付きます（無いと縦型でもショート棚に乗らないことがあります）。

**出す順番はショートが先です。** ショートで見つけてもらい、概要欄と末尾の導線で
長尺へ送る形にすると、長尺の総再生時間（YPPの3,000時間）が積みやすくなります。

**公開は1日に長尺1本・ショート1本まで。** 複数本ビルド・アップロード（限定公開）まで
進めても構いませんが、`--publish` はその日の分がまだなければ実行し、すでに出していれば
翌日以降に回してください。

**公開時刻は昼12時台（JST）が候補。** ビジネス系コンテンツは通勤時間帯・夜の
ゴールデンタイム（18-19時）を避け、昼休みに合わせると初動が伸びやすいという
一般論がある（2026-08-10 調査、一次データではなく業界記事ベースなので参考値）。
`--schedule` で予約公開できる。

```bash
python scripts/upload_youtube.py work/<id>-short --schedule "2026-08-11T03:00:00Z"  # JST 12:00
python scripts/upload_youtube.py work/<id>       --schedule "2026-08-11T03:10:00Z"  # JST 12:10、ショートの少し後
```

`--schedule` は `--publish` と違い即時公開せず、privacyStatus を private のまま
`publishAt` を仕込む。指定時刻に YouTube 側が自動で public に切り替える。

## 気をつけること

- **概要欄の冒頭の元動画URL・タイトルは自動で入ります。** 手で書かないでください
- **タイトル・概要欄・タグをテンプレの使い回しにしないこと。** YouTube の
  Inauthentic content ポリシーの対象になります
- **煽りサムネと誹謗中傷は禁止**（権利者ガイドライン）
- 収益化には YPP の条件に加えて再利用コンテンツ審査があります。
  図解カードが「元の配信に無い独自の付加価値」の根拠になるので、
  **カードを省いた手抜き版を出さないでください**

### 打った手（2026-08-13）

**1. 冒頭4秒の無音を消した。** `build_clip.py` は `[案件カード, 本編, 判定カード]`
を連結していて、カードは `anullsrc` の無音トラック付きの静止画だった。
実測で冒頭4秒が-91dB。いまはカードを本編に重ねるので音は0秒から鳴り、
尺も本編と一致する。ついでにカード1枚ごとの再エンコードをやめて1回にまとめた
（9枚で20分以上かかっていたビルドが2分半になった）。

**2. タイトルを競合の型に揃えた。** 既存16本に `sync_metadata.py` で反映済み。

**3. ショートを60〜70秒に詰めた。** 動きのある瞬間だけを取る。

**4. 長尺の既定を900秒にした。**

### まだ分かっていないこと

**上の4つはどれも検証されていない。** 3日で8本という母数では、冒頭の問題なのか
単に新規チャンネルの初期状態なのかを分離できない。

母数の差も大きい。競合は登録42,600人と32,700人で、ショートはまず登録者に配られる。
ただし**登録199人の「令和の虎切り抜きChannel」が22本で29万再生**を出しているので、
小さいチャンネルでは無理という話ではない。ここは在庫の中身（誰の回か）が効いている
可能性がある。

**既存8本のうち6本はすでに公開済みで、映像を直すと動画IDが変わる。**
公開済みのものは触らず、これから出すぶんで差を見るのが安全。
