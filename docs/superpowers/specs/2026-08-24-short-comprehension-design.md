# 設計：意味が伝わるショート切り抜き

最終更新: 2026-08-24

## なぜ作り直すのか

視聴者コメントが1件ついた。**このチャンネルに付いた唯一のコメントである。**

```
2026-08-19-akutsu-gyutan-short / nIulWMDR7dQ
[2026-08-22T13:32:15Z] @Tkkrchu: 「切り抜き方が下手でどういう意味なのか全くわからない」
```

（YouTube Data API `commentThreads.list` を公開済み26本に対して実行して取得。
他の動画にコメントは0件。`2026-08-20` の3本はコメントが無効になっている。）

指摘は正しい。実物を測って、原因が5つ見つかった。

## 測って分かった原因

### 1. 前提を切り落として、結論の接続詞から始まっている

`recipes/2026-08-19-akutsu-gyutan.json` の `short.start = 2275.0` の周辺の字幕:

| 秒 | 字幕 | 切り抜きに入るか |
| ---: | --- | --- |
| 2264.44 | ちょっとある推理していいですか? 僕 | ✗ |
| 2267.52 | 阿久津さんが今日全然元気なくプラス | ✗ |
| 2272.96 | 結構マイナスになることばっか言ってるじゃないですか。 | ✗ |
| **2275.00** | **← ここから切っている** | |
| 2275.96 | で、なんでかって言うと | ○ |
| 2279.72 | 今日ごめんなさいにしようとしてきてません。 | ○ |

推理の宣言も、その根拠も、全部カットの外にある。視聴者には *何の*
「なんでかって言うと」なのか分からない。前提の頭は **10.56秒手前**にある。

### 2. これは1本の事故ではない

`recipes/*.json` 19本を `work/<src>/subs.json` と突き合わせた結果、
**18本が字幕キューの途中から始まっている**（境界に乗っているのは
`yotsui-kakkoii` の1本だけ）。ズレは最大 +18.36秒（`komazawa-ginkou`）。

`scripts/recipe.py` の `validate_short()` は尺・`hook` の有無・範囲の整合しか
見ておらず、**開始点が発話の頭かどうかを一切見ていない。**

原因は構造的である。切り出し位置は信号のピーク（音量・詰め語彙）で決まる。
ピークは山の頂上であり、頂上には**そこへ至る登りが含まれていない。**

### 3. 65秒間ずっと同じ字幕1枚

`scripts/cards.py` の `render_short_frame()` は `head` と `quote` を焼いた
PNGを1枚返すだけで、`build_short.py` はそれを全区間に重ねている。
会話は進むのに文字は動かない。時間同期字幕はゼロ。

副作用として**話者が逆に見える。** `akutsu-gyutan` の0〜20秒に映っているのは
阿久津さん（志願者）だが、下に固定表示される
「今日『ごめんなさい』にしようとしてません?」は土橋社長（虎）の台詞である。
話者ラベルが無いので、画面の人物が自分でそう言っているように見える。

### 4. 元動画のテロップを自分で壊している

元動画には制作側が入れた要約テロップが画面下いっぱいに入っている
（2276秒地点で `マイナスな発言が多い`）。**これは理解の助けになる素材である。**

`build_short.py` は横を **1920 → 1166px（中央61%）** に詰めているため、
これが `ナスな発言が多` という読めない文字列に化けて画面中央に巨大に残る。
上隅の `志願者募集中!!` も同様に切れている。

### 5. 前提知識ゼロの視聴者への説明が無い

「ごめんなさい」が令和の虎で「出資しない」を指す用語だと知らない人には、
何の話か分からない。1〜4を直せば会話は追えるようになるので、
ここは 1〜4 の効果を見てから判断する。

## 合格条件（機械で測れる形にする）

1. `short.start` が字幕キューの境界に一致する（±0.15秒）
2. 開始直後のキューが接続詞・相槌だけの断片でない
3. 区間内の全キューが時間同期で焼かれている
4. 元動画テロップが横に切れた状態で画面に出ない

## 変更

### 変更1: 横のクロップをやめる（`build_short.py` / `cards.py`）

映像は 16:9 のまま **1080×608** で置く。元テロップが壊れず、下帯が広く空く。

| | いま | 変更後 |
| --- | --- | --- |
| 映像 | 1080×1000（横61%に寄せ） | 1080×608（等倍） |
| 上帯 | 460px：フック | 600px：フック |
| 下帯 | 460px：**固定字幕1枚** | 712px：**時間同期字幕** |

顔は小さくなる。README には「競合の上位はどれも大きく寄せている」と書いたが、
**寄せた結果が読めないテロップの残骸**なので、いまはこちらを取る。

### 変更2: `moments.rewind_to_topic_head()` — 話題の頭まで巻き戻す

```
rewind_to_topic_head(start, cues, max_back=15.0) -> float
```

`start` から最大 `max_back` 秒だけ遡り、**文末（`。？?！!`）の直後にあるキュー**
＝文の頭で止まる。ただし戻り先が相槌・断片なら、さらに1つ前へ。

断片とみなすもの:

- `[笑い]` `[拍手]` `[鼻息]` のような音の注記
- `はい。` `なるほど。` `えっ` のような相槌
- 3文字未満のキュー（ASRは `ほ` `お` のような1文字キューを吐く）

`max_back` 内に文頭が無ければ、元の `start` をそのまま返す（行き過ぎない）。

`build_short.py --dry-run` は**何秒戻したか・戻した先の字幕**を必ず出す。
自動の行き過ぎを目で止められる形にする。

### 変更3: `subtitles.burn_plan()` — ASR字幕を時間同期で焼く

`work/<src>/subs.json` の区間内キューを、既存のカードと同じ型
（キューごとにPNG → `overlay ... enable='between(t,s,e)'`）で下帯に焼く。

- キュー span は `[t_i, t_{i+1})`。最後のキューは区間の終わりまで
- 長いキューは **24文字程度で分割**し、時間を文字数で按分する
  （実測で最長12.0秒・107文字のキューが存在する）
- 既存の `quote`（固定引用）は**冒頭3秒だけ**フックとして残し、以降は字幕へ
- 1行が長すぎる場合は2行まで折り返す

**ASRの崩れを名指しする。** `--dry-run` は焼く全行を表示し、
数字・`万`・`億`・`円`・`%` を含む行を警告として名指しする。落とさない
（尺と素材の都合で通す判断があり得る）が、見ずに通ることは無くす。

実測された崩れの例: `土橋さん → その悪さん` / `焼き鳥3級 → 焼き鳥産`。

### 変更4: `validate_short()` に検証を足す

| 条件 | 挙動 |
| --- | --- |
| 巻き戻し後の尺 > 180秒 | 落とす（Shorts の仕様上限） |
| 巻き戻し後の尺 > 75秒 | 警告（伸びている競合は22〜73秒） |
| 区間内にキューが1つも無い | 落とす（字幕を焼けない＝意味が伝わらない） |
| `short.start` がキュー境界に乗っていない | 警告（巻き戻しが効くので落とさない） |

## やらないこと

**話者ラベルは入れない。** ASRに話者情報が無く、手書きゼロでは出せない。
時間同期字幕が入れば「画面の人が固定台詞を言っているように見える」問題は
消えるはずなので、まずここまでで実物を見る。効果が足りなければ後から
`short.speakers` を足す。

**投稿済み19本は作り直さない。** 映像を差し替える手段は無く、上げ直すと
動画IDが変わって再生数とコメントを失う。APIクォータも1日6本しかない。
仕組みを直し、**未投稿の4本**（`akutsu-hantei` / `imamura-ai` /
`komazawa-ginkou` / `yotsui-kakkoii`）から新しい形で出す。

**長尺（15分）は今回触らない。** コメントはショートに対して付いた。
長尺は冒頭に案件カードが出るぶん前提が入っている。ショートの効果を見てから。

## 検証

1. `pytest` — 既存109件を壊さない。新規に以下を足す
   - 巻き戻し: 文頭で止まる／相槌を越える／`max_back` で諦める／キューが無い
   - 字幕分割: 長いキューの分割と時間按分／2行折り返し／区間の端の扱い
   - 検証: 180秒超で落ちる／75秒超で警告／キュー0件で落ちる
2. 未投稿4本を実ビルドし、**フレームを抜いて画像で確認する**
3. 巻き戻しの before/after を全19本ぶん一覧で出す
